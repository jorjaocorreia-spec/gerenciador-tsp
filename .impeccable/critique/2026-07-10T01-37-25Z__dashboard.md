## Anti-Patterns Verdict

**LLM assessment**: Does not read as AI-generated. No gradient text, no hero-metric template, no generic Bootstrap-card layout; the empty state is terse, not AI-flowery. The real defect is *design-system entropy*, not slop: the Dashboard alone uses at least four different violets and two off-token status colors, which is exactly the failure DESIGN.md's "One Accent Rule" and "Functional Color Rule" were written to prevent.

**Deterministic scan**: `detect.mjs --json index.html` — exit 2, 111 findings file-wide; 12 fall inside `#view-dashboard` (all `advisory`: `design-system-font-size` ×7, `design-system-color` ×5), all on inline styles for the "Horas do Mês"/"Insights" buttons, the "Totalizar Horas" checkbox/label, and the AI Insights panel. Browser-injected live scan (whole SPA DOM, since all views coexist hidden in the same document) found 88 anti-patterns total, including several `low-contrast` hits directly relevant to Dashboard controls: white/near-white text on `#8b5cf6` at 4.0–4.2:1 (below the 4.5:1 AA threshold) recurring 7+ times, plus one severe outlier at 2.2:1 (`#f8fafc` on `#22c55e`) elsewhere in the app. `layout-transition` on `width` is pre-existing/intentional (documented sidebar-collapse animation). `overused-font` (Inter) and `ai-color-palette`/`dark-glow` (violet-on-dark) are the project's documented, deliberate identity per DESIGN.md, not defects. Three `skipped-heading` findings belong to the Agenda/Indicadores/invite-user modal, not the Dashboard, and are excluded from this critique.

**Visual overlays**: Browser injection succeeded (Playwright session, logged in as `testes@teste.com`), but the test account has zero registered clients, so only the empty state was evidenced pixel-for-pixel; the populated card grid could not be visually verified in this run and was assessed from source only. No overlay tab was left open for the user — the live-server instance used for evidence collection was stopped after the scan.

## Overall Impression

The Dashboard's information architecture is sound — one clear task, sensible grouping, low cognitive load (1 of 8 checklist items failed). The gap between "good bones" and "shipped confidently" is entirely in execution: color tokens drift from the project's own documented system on this exact screen, contrast on the primary accent is measurably under WCAG AA in several places, and the single most-used interactive element (client cards) is invisible to keyboard navigation. The biggest opportunity is a token-consistency + accessibility pass specifically on this screen, not a redesign — the underlying structure doesn't need to change.

## What's Working

1. **Over-limit card treatment is well-judged restraint** — the pulse/glow only fires on cards genuinely over budget, functional color use exactly as DESIGN.md intends.
2. **The "Totalizar Horas" info-tooltip is a model of contextual help** — explains a non-obvious saldo formula inline, keyboard-reachable (`tabindex="0"`, `focus-within`), no modal needed.
3. **The month-navigation state machine guards against stale renders** — a `_dashRenderGen` counter discards outdated async responses when the user clicks through months quickly, real engineering discipline that protects the "trust the number" promise.

## Priority Issues

**[P1] Accent color drift breaks the project's own "One Accent Rule"**
- **Why it matters**: DESIGN.md names this exact failure mode. Four visibly different violets (`#8b5cf6`, `#a855f7`, `#a78bfa`, plus various alpha variants) sitting within the same viewport as the correctly-toned sidebar reads as inconsistent, not premium, on a screen meant to project "confiança visual = seriedade percebida".
- **Fix**: Replace every off-token violet and off-token status color (`#4ade80`/`#f87171`) inside `#view-dashboard` with `var(--primary-color)`/`var(--primary-hover)`/`var(--success-color)`/`var(--danger-color)`.
- **Suggested command**: `/impeccable harden`

**[P1] Contrast failures on the primary violet accent**
- **Why it matters**: Detector found white/near-white text on `#8b5cf6` recurring at 4.0–4.2:1 (below the 4.5:1 AA text threshold) across several buttons, plus one severe 2.2:1 outlier (white on green badge) elsewhere in the app. This is a measurable accessibility failure, not a judgment call, on the app's single accent color.
- **Fix**: Darken the violet slightly for text-bearing surfaces or increase text weight/size to qualify for the 3:1 large-text threshold; audit and correct the green-badge instance specifically.
- **Suggested command**: `/impeccable harden`

**[P1] Dashboard cards are not keyboard-focusable**
- **Why it matters**: Client cards are the most-clicked element on this screen and are built as plain `<div>`s with only `.onclick` — no `tabindex`, no `role="button"`, no keyboard handler. This is a genuine WCAG 2.1.1 keyboard-access failure, not a nitpick, and directly contradicts DESIGN.md's own accessibility commitment ("foco visível em todos os elementos interativos").
- **Fix**: Add `tabindex="0"`, `role="button"`, `aria-label`, and an Enter/Space `keydown` handler mirroring the click handler.
- **Suggested command**: `/impeccable harden`

**[P1] Empty state doesn't distinguish "no clients" from "no clients match your filter"**
- **Why it matters**: The literal string "Nenhum cliente cadastrado ainda." shows whenever the filtered list is empty, even if the account has clients that are simply filtered out (e.g. all "Finalizado" with the default "Ativos" filter). For a tool whose stated success metric is "the consultant trusts the number the screen shows," a false "nothing registered" message is directly disorienting.
- **Fix**: Branch the copy — true zero-clients gets a "Novo Cliente" CTA; filtered-to-zero gets a message naming how many are hidden plus a one-click "mostrar todos".
- **Suggested command**: `/impeccable clarify`

**[P2] Card animations don't respect `prefers-reduced-motion`**
- **Why it matters**: PRODUCT.md commits to `prefers-reduced-motion` support, but the cascade-in on every render and the infinite over-limit pulse are both unguarded — and the over-limit pulse is attached to the highest-stakes card on the screen, exactly where persistent motion is most likely to bother a vestibular-sensitive user.
- **Fix**: Wrap `.stat-card-animate`, `.stat-card.over-limit`'s pulse, and the JS counter/bar animations in a `prefers-reduced-motion: reduce` override.
- **Suggested command**: `/impeccable harden`

## Persona Red Flags

**Alex (Power User)**: Opens the Dashboard between calls wanting to check three clients' balances in ten seconds — can't tab through cards at all, every lookup requires a precise mouse click. Switching to "Totalizar Horas" mode silently changes what every number means with no visual cue distinguishing the two modes.

**Sam (Accessibility-Dependent)**: Tab order jumps from "Insights" to the filter checkboxes to the month-nav chevrons, then stops — client cards, the entire point of the screen, are invisible to keyboard nav and have no `role`/`aria-label` connecting the over-limit alarm state to anything but color and a pulsing glow.

## Minor Observations

- "Horas do Mês"/"Insights" buttons at 13px with 6px/14px padding are under the 44×44pt touch-target guidance if ever used on a tablet.
- `card.title = "Projeto: X"` relies on the native browser tooltip — functional but undiscoverable, and inaccessible to touch/keyboard users.
- Balance-mode card's number (`font-weight: 700; font-size: 1.05rem`) borders on the hero-metric pattern DESIGN.md's Don'ts warn against — not egregious yet, worth watching.
- AI Insights panel's close control is a raw "✕ Fechar" text glyph, inconsistent with the icon-first pattern (Lucide) used everywhere else on this view.
- Native unstyled checkboxes ("Ativos"/"Finalizados") render as plain light-mode OS squares on a near-black canvas — the single most visually "undesigned" element on the screen; no `color-scheme: dark` declared anywhere in `main.css`.
